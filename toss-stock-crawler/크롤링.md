# 토스증권 종목 커뮤니티 크롤링 명세서 (`크롤링.md`)

> 네이버 증권 버전(`naver-stock-crawler`)과 **동일한 평면형(Flat) JSON 스키마 및 아키텍처**를 유지하여 추후 두 플랫폼의 데이터를 충돌 없이 통합 분석할 수 있도록 설계하되, **토스증권 커뮤니티(`tossinvest.com`) 고유의 UI·API 특성**을 반영한 명세서입니다.

---

## 1. 수집 대상 및 항목
토스증권 웹(`https://tossinvest.com/stocks/{toss_code}/community`)의 종목 커뮤니티 게시글 및 댓글/대댓글을 대상으로 아래 항목을 수집합니다.

* **URL 및 종목코드 변환 규칙:**
  * 사용자가 국내 6자리 종목코드(예: `005930`)를 입력하면 접속 URL은 자동으로 `A` 접두사를 붙여 `https://tossinvest.com/stocks/A005930/community`로 변환합니다. (해외주식 심볼이나 이미 `A`/`US` 접두사가 있는 경우 그대로 사용)
  * JSON에 저장되는 `stock_code`는 네이버 데이터와의 호환을 위해 국내주식의 경우 6자리 숫자(`"005930"`)로 통일합니다.

| 항목명 | 필드명 (JSON Key) | 타입 | 설명 (토스증권 적용 규칙 포함) |
| :--- | :--- | :--- | :--- |
| **고유 ID** | `id` | `string` | 게시글/댓글/대댓글 고유 식별자. 네이버 데이터와 병합 시 충돌 방지를 위해 플랫폼 접두사 권장 (예: `"toss_post_123456"`, `"toss_comment_78901"`, `"toss_reply_78902"`) |
| **출처 플랫폼** | `source` | `string` | 데이터 출처 구분자 (토스증권은 항상 `"toss"`, 네이버 데이터와 통합 분석 시 식별용) |
| **항목 유형** | `item_type` | `string` | `"post"` (원글), `"comment"` (일반 댓글), `"reply"` (대댓글) 구분 |
| **상위 글 연결 정보** | `parent_id` | `string \| null` | 댓글일 경우 원글 `id`, 대댓글일 경우 상위 댓글의 `id` (원글은 `null`) |
| **원글 ID** | `root_post_id` | `string` | 해당 댓글/대댓글이 속한 최상위 게시글의 `id` |
| **종목명** | `stock_name` | `string` | 수집 대상 주식 종목명 (페이지 상단 또는 API 응답에서 자동 추출, 예: `"삼성전자"`) |
| **종목코드** | `stock_code` | `string` | 수집 대상 주식 종목코드 (국내주식 6자리 통일, 예: `"005930"`) |
| **닉네임** | `nickname` | `string` | 작성자 닉네임 |
| **주주 여부** | `is_shareholder` | `boolean` | 닉네임 옆 **'주주'** 인증 배지 표시 여부 (`true` / `false`) |
| **작성시간** | `created_at` | `string` | 작성 일시 (`YYYY.MM.DD HH:MM`). 토스 피드 DOM은 `'3분 전'` 등 상대시간이 많으므로 **백그라운드 JSON 응답(`createdAt` 등 ISO 절대시간)을 최우선**으로 사용하고, 없을 경우 `scraped_at` 기준으로 보정 |
| **수집시각** | `scraped_at` | `string` | 크롤러가 해당 데이터를 수집한 시각 (`YYYY-MM-DD HH:MM:SS`) |
| **글 제목** | `title` | `string \| null` | 게시글 제목. 토스증권은 SNS 피드형이라 제목이 없는 글이 대부분이므로 **원글(`post`)이라도 제목이 없으면 `null` 허용** (댓글/대댓글도 `null`) |
| **글 내용** | `content` | `string` | 게시글 본문 또는 댓글/대댓글 텍스트 내용 (긴 글에 `'더보기'`가 있으면 확장 후 원문 전체 수집) |
| **좋아요 / 싫어요** | `like_count`, `dislike_count` | `integer` | 좋아요(하트) 수 및 싫어요 수. **토스증권은 싫어요 기능이 없으므로 `dislike_count`는 네이버 스키마 호환을 위해 `0`으로 고정** |
| **첨부 사진 URL** | `image_urls` | `array<string>` | 본문/댓글 내 첨부 이미지가 있는 경우 **이미지 URL 문자열 배열만 저장** (파일 다운로드 없음, 없으면 `[]`) |
| **원본 URL** | `post_url` | `string` | 해당 게시글의 URL (**반드시 순수 문자열 처리**) |

## 2. 사용자 설정 가능한 수집 범위 (실행 옵션)
크롤러 실행 시 사용자가 수집 대상 주식과 수집 범위를 직접 설정할 수 있도록 대화형 입력(`input`) 및 CLI 인자(`argparse`)를 모두 지원합니다.

* **대상 주식 (`--code` 또는 `--stock`):** 수집할 주식의 6자리 종목코드(예: `005930`) 또는 토스 종목코드(`A005930`, 해외 심볼 등) 입력 — 페이지 접속 시 종목명(`stock_name`) 자동 추출
* **정렬 기준 (`--sort`):** 기본값 **`latest` (최신순)** — `--max-posts` 및 `--since-date` 기준 수집을 위해 커뮤니티 진입 직후 **'최신순' 탭으로 자동 전환** (선택적으로 `popular` 인기순 지정 가능)
* **수집 범위 모드 (택1 또는 병행):**
  1. **수집할 게시글 수 (`--max-posts`):** 최신 글부터 지정한 개수(예: `50`개)만큼의 원글(및 그에 속한 모든 댓글/대댓글) 수집
  2. **수집 종료 기준 날짜 (`--since-date`):** 지정한 날짜(예: `2026-11-18`)까지 작성된 모든 원글(및 댓글/대댓글) 수집
* **출력 파일 경로 (`--output`):** 저장할 JSON 파일명 (기본값: `output/output_toss_{종목명}_{종목코드}.json`)

## 3. 크롤링 도구 및 환경 설정

### 3.1 사용 도구 (Playwright + Network JSON 하이브리드 필수)
* **주력 도구:** **Playwright** (`playwright.async_api`)
* **하이브리드 네트워크 가로채기 (`page.on("response")`):**
  * 토스증권 웹은 React 기반 SPA(Single Page Application)이며 피드 목록에서 정확한 작성시간(`createdAt`), 게시글/댓글 고유 ID, 주주 인증 여부 등이 백그라운드 JSON API(`wts-info-api.tossinvest.com`, `wts-cert-api.tossinvest.com` 등 커뮤니티 API)로 전달됩니다.
  * 따라서 Playwright로 실제 화면을 조작하면서 동시에 백그라운드 JSON 응답을 가로채어 DOM 추출과 상호 보완하는 **하이브리드 구조**를 기본으로 채택합니다.

### 3.2 브라우저 창 띄워두기 (시각적 모니터링)
* 크롤링 진행 상황을 눈으로 직접 확인할 수 있도록 브라우저를 화면에 표시합니다.
* 설정값:
  ```python
  browser = await playwright.chromium.launch(headless=False)
  ```

### 3.3 토스증권 전용 진입 처리 (클린봇 대체 및 로그인 모달 대응)
* **클린봇(Cleanbot) 해제 불필요:** 네이버 전용 기능이므로 토스증권에서는 수행하지 않습니다.
* **'최신순' 정렬 전환:** 커뮤니티 접속 직후 기본 탭이 '인기순'인 경우 사람처럼 **'최신순' 버튼/탭을 클릭**하여 시간순으로 수집합니다.
* **비로그인 제한 / 로그인 유도 모달 대응:**
  * 일정 스크롤 이상 또는 댓글 상세 조회 시 로그인 유도 팝업이 나타날 경우, 팝업 닫기 버튼을 먼저 시도합니다.
  * 로그인이 반드시 필요한 경우 `headless=False` 화면에서 사용자가 직접 QR/앱 로그인을 완료할 수 있도록 대기(`input` 또는 로그인 완료 감지)하고, 필요 시 브라우저 세션(`user_data_dir`)을 유지할 수 있는 옵션을 지원합니다.

## 4. 인간 행동과 유사한 크롤링 동작 (Human-like Interaction)
단조로운 기계적 요청 패턴으로 인한 차단을 방지하기 위해 실제 사용자가 피드를 탐색하는 것과 유사한 동작을 구현합니다.

1. **자연스러운 마우스 커서 움직임**
   * 요소를 클릭하기 전에 현재 마우스 위치에서 대상 요소의 좌표까지 여러 단계(`steps`)로 나누어 부드럽게 곡선 이동합니다.
   * 클릭 위치 또한 요소의 정중앙 고정 좌표가 아닌, 요소 영역 내 약간의 랜덤 오프셋(`±px`)을 부여합니다.
2. **자연스러운 타이핑 속도와 딜레이**
   * 검색어 입력 등 타이핑이 필요할 때 글자마다 랜덤한 입력 지연 시간(`50~150ms`)을 두어 입력합니다.
3. **무한 스크롤 피드 탐색 및 짧은 대기**
   * 토스증권은 SNS형 무한 스크롤 피드이므로 한 번에 끝까지 점프하지 않고, `page.mouse.wheel`로 자연스럽게 나누어 스크롤합니다.
   * 스크롤 동작 직후 사람이 글을 읽는 것처럼 짧은 랜덤 대기 시간(`1.0~2.8초`)을 부여합니다.
4. **긴 글 및 댓글/대댓글 확장**
   * 피드 카드에 `'더보기'`가 있으면 클릭하여 본문 전체를 펼칩니다.
   * 댓글이 달린 게시글은 댓글 영역/상세를 열어 `'댓글 더보기'`, `'답글 N개 보기'` 등의 버튼을 사람처럼 클릭해 모두 펼친 뒤 누락 없이 수집합니다.

## 5. 데이터 저장 및 JSON 포맷 규칙

### 5.1 JSON 저장 기본 원칙 (평면형 Flat 구조)
* **구조 방식:** 원글(`post`), 댓글(`comment`), 대댓글(`reply`)을 중첩하지 않고 **평면형(Flat) JSON 배열**에 동일한 스키마로 저장하며 `id`, `parent_id`, `root_post_id`로 계층 관계를 연결합니다.
* **인코딩 및 한글 깨짐 방지:** 파일 저장 시 반드시 `encoding="utf-8"`, `json.dump(..., ensure_ascii=False, indent=2)`를 적용합니다.
* **모든 URL의 문자열(String) 강제 처리:** `post_url` 및 `image_urls` 배열 내 모든 원소는 별도 파일 다운로드나 링크 객체 변환 없이 **순수 문자열(`str`)**로만 저장합니다.

## 6. 예외 처리 및 안정성 규칙
1. **중간 저장(Checkpointing) 및 이어하기:** 장시간 크롤링 중 오류로 중단되더라도 수집된 데이터가 유실되지 않도록 **게시글 1개 세트(원글+댓글+대댓글) 수집이 끝날 때마다 원자적(Atomic) 파일 쓰기로 즉시 JSON 파일에 반영**하고, 재실행 시 이미 수집된 `id`는 건너뜁니다.
2. **접힌 본문 및 댓글/대댓글 확장:** 긴 본문의 `'더보기'` 및 접힌 댓글/대댓글(`'댓글 더보기'`, `'답글 N개 보기'`)을 감지하여 사람처럼 클릭·확장한 뒤 수집합니다.
3. **디렉토리 구조 분리:** 설정(`config/`), 프로그램 코어(`src/`), 결과 데이터(`output/`), 실행 로그(`logs/`), 진입점(`main.py`)으로 명확히 분리하여 관리합니다.
