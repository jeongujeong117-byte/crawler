# 네이버 증권 종목토론방 크롤링 명세서 (`크롤링.md`)

## 1. 수집 대상 및 항목
네이버 증권(네이버페이 증권) 종목토론방(`m.stock.naver.com`)의 게시글 및 댓글/대댓글을 대상으로 아래 항목을 수집합니다.

| 항목명 | 필드명 (JSON Key) | 타입 | 설명 |
| :--- | :--- | :--- | :--- |
| **고유 ID** | `id` | `string` | 게시글 번호(`nid`) 또는 댓글/대댓글 고유 식별자 (연결의 기준값) |
| **항목 유형** | `item_type` | `string` | `"post"` (원글), `"comment"` (일반 댓글), `"reply"` (대댓글) 구분 |
| **상위 글 연결 정보** | `parent_id` | `string \| null` | 댓글일 경우 원글 `id`, 대댓글일 경우 상위 댓글의 `id` (원글은 `null`) |
| **원글 ID** | `root_post_id` | `string` | 해당 댓글/대댓글이 속한 최상위 게시글의 `id` |
| **종목명** | `stock_name` | `string` | 수집 대상 주식 종목명 (페이지 상단에서 자동 추출, 예: `"삼성전자"`) |
| **종목코드** | `stock_code` | `string` | 수집 대상 주식 6자리 종목코드 (예: `"005930"`) |
| **닉네임** | `nickname` | `string` | 작성자 닉네임 (마스킹된 ID 또는 프로필명) |
| **주주 여부** | `is_shareholder` | `boolean` | 닉네임 옆 **'주주'** 인증 배지 표시 여부 (`true` / `false`) |
| **작성시간** | `created_at` | `string` | 작성 일시 (상세 페이지의 절대 시간 `YYYY.MM.DD HH:MM` 우선, 상대 시간일 경우 `scraped_at` 기준 보정) |
| **수집시각** | `scraped_at` | `string` | 크롤러가 해당 데이터를 수집한 시각 (`YYYY-MM-DD HH:MM:SS`) |
| **글 제목** | `title` | `string \| null` | 게시글 제목 (댓글/대댓글인 경우 `null`) |
| **글 내용** | `content` | `string` | 게시글 본문 또는 댓글/대댓글 텍스트 내용 |
| **좋아요 / 싫어요** | `like_count`, `dislike_count` | `integer` | 공감(좋아요) 수 및 비공감(싫어요) 수 |
| **첨부 사진 URL** | `image_urls` | `array<string>` | 본문 내 사진이 포함된 경우 **이미지 URL 문자열 배열만 저장** (파일 다운로드 없음, 사진이 없으면 `[]`) |
| **원본 URL** | `post_url` | `string` | 해당 게시글의 URL (**반드시 순수 문자열 처리**) |

## 2. 사용자 설정 가능한 수집 범위 (실행 옵션)
크롤러 실행 시 사용자가 수집 대상 주식과 수집 범위를 직접 설정할 수 있도록 대화형 입력(`input`) 및 CLI 인자(`argparse`)를 모두 지원합니다.

* **대상 주식 (`--code` 또는 `--stock`):** 수집할 주식의 6자리 종목코드(예: `005930`) 또는 종목명 입력 (페이지 접속 시 해당 종목명 `stock_name`을 자동 추출하여 데이터에 함께 기록)
* **수집 범위 모드 (택1 또는 병행):**
  1. **수집할 게시글 수 (`--max-posts`):** 최신 글부터 지정한 개수(예: `50`개)만큼의 원글(및 그에 속한 모든 댓글/대댓글) 수집
  2. **수집 종료 기준 날짜 (`--since-date`):** 지정한 날짜(예: `2026-11-18`)까지 작성된 모든 원글(및 댓글/대댓글) 수집
* **출력 파일 경로 (`--output`):** 저장할 JSON 파일명 (기본값: `output_{종목명}_{종목코드}.json`)

## 3. 크롤링 도구 및 환경 설정

### 3.1 사용 도구
* **주력 도구:** **Playwright** (Python `playwright.async_api` 또는 `playwright.sync_api`)
* **대체 도구 (차단 또는 제약 발생 시):**
  * 브라우저 자동화 대안: `Nodriver`, `DrissionPage`, `Undetected-Chromedriver (Selenium)`
  * 하이브리드 대안: Playwright로 실제 브라우저를 움직이면서 백그라운드 JSON 통신을 가로채는 방식(`page.on("response")`) 또는 `curl_cffi`

### 3.2 브라우저 창 띄워두기 (시각적 모니터링)
* 크롤링 진행 상황을 눈으로 직접 확인할 수 있도록 브라우저를 화면에 표시합니다.
* 설정값:
  ```python
  browser = playwright.chromium.launch(headless=False)
  ```

### 3.3 클린봇(Cleanbot) 해제
* 페이지 접속 후 크롤링을 시작하기 전에 **클린봇 설정을 OFF(해제)**하여 가려지는 게시글이나 댓글 없이 원문 전체가 노출된 상태에서 수집을 진행합니다.

## 4. 인간 행동과 유사한 크롤링 동작 (Human-like Interaction)
단조로운 기계적 요청 패턴으로 인한 차단을 방지하기 위해 실제 사용자가 브라우저를 탐색하는 것과 유사한 동작을 구현합니다.

1. **자연스러운 마우스 커서 움직임**
   * 요소를 클릭하기 전에 현재 마우스 위치에서 대상 요소의 좌표까지 여러 단계(`steps`)로 나누어 부드럽게 커서를 이동합니다.
   * 클릭 위치 또한 요소의 정중앙 고정 좌표가 아닌, 요소 영역 내 약간의 랜덤 오프셋을 부여합니다.
2. **자연스러운 타이핑 속도와 딜레이**
   * 검색어 입력이나 텍스트 타이핑 시 텍스트를 한 번에 붙여넣지 않고, 글자마다 랜덤한 입력 지연 시간(`delay=random.randint(50, 150)` ms)을 두어 타이핑합니다.
3. **스크롤 후 짧은 대기**
   * 페이지 하단으로 이동하거나 댓글/게시글 목록을 읽을 때 한 번에 끝까지 점프하지 않고, 마우스 휠(`page.mouse.wheel`)로 자연스럽게 나누어 스크롤합니다.
   * 스크롤 동작 직후 사람이 글을 읽는 것처럼 짧은 랜덤 대기 시간(`time.sleep(random.uniform(1.0, 2.8))`)을 부여합니다.
4. **페이지 전환 및 클릭 간 가변 딜레이**
   * 게시글 진입, 댓글/대댓글 펼치기(`답글 보기`), 뒤로 가기, 페이지 이동 사이에 고정된 초(`sleep(2)`)가 아닌 난수 기반의 가변 대기 시간을 적용합니다.

## 5. 데이터 저장 및 JSON 포맷 규칙

### 5.1 JSON 저장 기본 원칙 (평면형 Flat 구조)
* **구조 방식:** 원글(`post`), 댓글(`comment`), 대댓글(`reply`)을 모두 동일한 레벨의 **평면형(Flat) JSON 배열**에 저장하고, `id`, `parent_id`, `root_post_id`로 계층 관계를 연결합니다.
* **인코딩 및 한글 깨짐 방지:** 파일 저장 시 반드시 `encoding="utf-8"` 및 `json.dump(..., ensure_ascii=False, indent=2)`를 적용합니다.
* **모든 URL의 문자열(String) 강제 처리:**
  * 수집된 게시글 URL(`post_url`) 및 첨부 사진 URL(`image_urls` 배열 내 원소)은 별도 파일 다운로드나 링크 객체 변환 없이 **순수 문자열(`str`)**로만 저장합니다.

## 6. 예외 처리 및 안정성 규칙
1. **중간 저장(Checkpointing) 및 이어하기:** 장시간 크롤링 중 오류로 중단되더라도 수집된 데이터가 유실되지 않도록 게시글 단위로 즉시 JSON 파일에 반영하고, 재실행 시 이미 수집된 `id`는 건너뜁니다.
2. **접힌 댓글/대댓글 확장:** 댓글이 많거나 대댓글이 접혀 있는 경우(`답글 N개 보기`, `댓글 더보기`), 해당 버튼을 감지하여 클릭·확장한 뒤 수집합니다.
